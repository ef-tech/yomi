# 削除ボタンを全行に足したときの DOM 構築コスト（Issue #171）

`bun run bench 1000 5000 10000` の実測（同一マシン・同一セッションで前後を測った）。
測り方は `tree-baseline.md` / `tree-diff-notify.md` と同じで、**DOM 構築は jsdom 上の値**
（レイアウト・ペイントを含まない）。

## なぜ測ったか

削除ボタンは**ファイルにもディレクトリにも付く**ので、これまでの「＋」（ディレクトリだけ、
10,000 ノードで 500 個）と違い、**ノード数ぶんそのまま増える**。#84 → #126 で削ってきた
初回描画に直接効くため、入れる前に前後を取った。

## 結果（DOM 構築、単位 ms・中央値）

| ノード数 | 変更前 | 行ごとにリスナ + `data-*` | **委譲（採用）** |
|---|---|---|---|
| 1,000 | 23.4 | 34.5 | **28.4** |
| 5,000 | 105.8 | 181.3 | **147.4** |
| 10,000 | 217.8 | 334.3 | **314.1** |

`watcher` イベント 1 回あたりの反映（差分更新の経路）は **0.1ms のまま変わらない** ——
増えるのは初回描画だけで、保存やライブリロードの体感には出ない。

## 何をして削ったか

**行ごとの `addEventListener` と `data-*` をやめ、ツリー全体で 1 つのリスナに委譲した**
（`public/app-tree.js` の `createDeleteButton` / `wireTreeToolbar`）。対象は `li` の
`data-node-key`（`${type}:${path}`。差分更新のために必ず振ってある）から引く。

- 10,000 ノードで **-20ms**、そしてリスナが 10,000 個 → 1 個になる
- 残る差（218 → 314ms）は**ボタン要素そのものと `title` / `aria-label`** のぶん。
  ここを削るには「hover 中の 1 行にだけボタンを差し込む」形にするしかないが、
  **`Tab` フォーカスで到達できなくなる**（「＋」を常設している理由と同じ）ので採らなかった

## 判断

**受け入れる。** 影響は初回描画だけで、差分更新は無傷。1,000 ノード規模では +5ms で、
10,000 ノードは `bench` の上限として置いている極端なケース。**これ以上はアクセシビリティを
削ることになる**ため、そのトレードオフはしない。
