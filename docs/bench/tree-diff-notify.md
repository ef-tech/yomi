# ツリー差分通知の前後比較（Issue #126）

`bun run bench 1000 5000 10000` の実測。前段は #84（`docs/bench/tree-diff-update.md`）で、
そこで残った **18ms の壁**を崩すのがこの Issue。

## 何を変えたか

**サーバが「どこがどう変わったか」を送るようにした。** これまでの `tree` 通知は
「形が変わった」としか言っておらず、受け取った側は `/api/tree` を全量取り直して
**10,500 ノードを突き合わせる**しかなかった。

- `src/watcher.ts`: `add` / `unlink` を `"rename"` に畳むのをやめた（畳んだままでは
  追加か削除かを送れない）
- `src/server.ts`: `{ type: "tree", op, path, gen }` を送る。`gen` はツリーの版
- `public/tree-diff.js`: 手元のツリーへ 1 件だけ当てる（`src/scanner.ts` の
  並び順と `pruneEmpty` を再現する）
- `public/app-tree.js`: **変わったディレクトリの `<ul>` だけ**を突き合わせる

## 結果

### watcher イベント 1 回あたりの反映コスト

単位 ms、中央値 (最小–最大)。**変更前は #84 時点の値**（`tree-diff-update.md` の
「変更後」列）。

| ファイル数 | 変更前（末尾） | 変更後（末尾） | 変更前（先頭） | 変更後（先頭） |
|---|---|---|---|---|
| 1,000 | 1.4 (1.3–2.6) | **0.1 (0.1–0.1)** | 1.5 (1.4–2.8) | **0.1 (0.1–0.2)** |
| 5,000 | 9.1 (7.6–11.5) | **0.1 (0.1–0.1)** | 8.8 (7.0–10.0) | **0.0 (0.0–0.1)** |
| 10,000 | 18.2 (17.0–19.2) | **0.0 (0.0–0.1)** | 17.8 (17.3–18.8) | **0.0 (0.0–0.1)** |

**DoD の「18ms → 5ms 以下」は満たしている。** ファイル数を 10 倍にしても値が
増えないのは、見る範囲が**変わったディレクトリの中だけ**（fixture では 1 ディレクトリ
あたり 20 ファイル）になり、木全体の大きさから切り離されたため。

**計測の範囲が変わっている点に注意。** #84 までのこの列は `/api/tree` の取得を含んで
いたが、いまはその取得自体が経路から消えた。**「取得 + 反映」から「反映だけ」への
比較**なので、内訳ではなく**利用者が待つ時間**として読むこと。

### 計測に入っていないもの

**クイックオープンの母集団の作り直し**（`collectFilePaths`）は bench のハーネスに
無いので上の列に入っていない。実物は差分のたびに呼ぶので、別途実測した:

| ファイル数 | `collectFilePaths` |
|---|---|
| 10,000 | 0.12 (0.09–0.15) |

DOM を触らない純粋な走査なので安い。**1 イベントあたりの実コストは
おおよそ 0.1 + 0.12 ≒ 0.25ms** で、DoD の 5ms に対しては十分な余裕がある。
これ以上を削るなら母集団も差分で持つことになるが、いまは必要ない。

### `/api/tree` の応答時間・応答サイズは変えていない

| ファイル数 | `/api/tree` | response size |
|---|---|---|
| 1,000 | 0.1 (0.1–0.2) | 68 KiB |
| 5,000 | 0.2 (0.2–1.4) | 358 KiB |
| 10,000 | 0.4 (0.4–0.5) | 724 KiB |

**この経路は「取りこぼしたとき」と「起動・再接続時」にしか通らなくなった。**
#84 のキャッシュがそのまま効いている。

### 初回描画は変えていない

DOM 構築（10,000 で 262.2ms）は #84 から手を付けていない。差分通知は
「2 回目以降」の話で、初回は全量を描くしかない。

## 測り方で変えたこと

**`measureWatcherRefresh` から `/api/tree` の取得を外した。** 残しておくと、
**無くしたはずのコストを測り続ける**ことになる（差分が効いていても数値が下がらない）。

**変更位置を名前で決めるようにした。** 以前は `splice` の添字で先頭 / 末尾を
指定していたが、`applyTreeDiff` は**名前順の位置**へ入れるので添字では決められない。
`0000-bench.md`（先頭）と `zzz-bench.md`（末尾）を使う。

**`add` から始める。** まだ無いファイルの削除は「何もしない」で成功扱いになるので、
`remove` から始めると 1 周目が空振りし、**「何も変わらないときのコスト」**を測ってしまう
（#84 でも同じ罠を踏んでいる）。

## 環境

```
yomi v0.21.1 / bun 1.3.12 / linux / Intel(R) Core(TM) Ultra 7 265K x20 / RAM 61 GB
```

**#84 の計測と同じマシン**（`tree-diff-update.md` の「Intel Core Ultra 7 265K (20 コア) /
RAM 61 GB」）。上の「変更前 / 変更後」はそのまま並べて読める。

warmup 3 回を捨てたあと 11 回計測、中央値 (最小–最大)。
